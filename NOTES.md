# Hold 60: build notes

## Design decisions

- **The name is Hold 60.** It's a verb plus the goal, it reads well in an HN title ("Show HN: Hold 60 – keep a power grid at 60 Hz for a day, or write the dispatch code"), and the "60" in the wordmark changes color with the live frequency. Alternatives are in the README.
- **Fleets, not individual plants.** Each resource is a fleet of identical units with one slider. The target decides how many units run: drag above what's online and units start, but only produce after their start-up delay. One control per fleet keeps the 390 px layout usable, and the unit strip (solid, striped, hatched) still shows commitment. Code mode adds `commit` so policies can warm units without producing.
- **The battery responds to frequency by itself.** Without that, a human at 1× would need minute-by-minute reflexes. With it, small errors cost battery charge rather than blackouts, and the drama becomes "the battery is running out" instead of "I can't click fast enough". Its state of charge is a resource you spend.
- **Rolling blackouts come from the rules, not a script.** Shedding happens in 5% stages below 59.3 Hz, and power comes back after 20 healthy minutes. If you're still short it gets cut again, so rolling blackouts emerge on their own.
- **Over-frequency trips a unit.** This punishes over-generation in a realistic way and caused the most interesting failure in testing: in the AI-boom day, the day-ahead baseline over-frequencies on a checkpoint, trips, and collapses into shedding.
- **Inertia scales with spinning generation**, so the needle gets twitchier when solar carries the grid. It's a small thing, but it's real grid physics that HN readers like to see.
- **Score = cost to society** (fuel + starts + wear + DR + $10k/MWh unserved + $100/t CO₂), with blackouts capping the grade. One number keeps code mode comparable, and blackouts still dominate in practice.
- **Par = the best of our reference policies, not "best known".** Each day's par is the cheapest zero-blackout result from the baselines, the hidden expert, a reactive policy, or `tunedSimple` (all in `tools/expert-policy.mjs`; `tunedSimple` is the policy the README used to print). The README example is deliberately NOT in that set: a test requires it to stay above par (never A+) on every day. Gas-first policies still beat par on some days (see leftovers), so the UI calls par a target, shows the score in $M and "% vs par", and the share text carries both.
- **All randomness is drawn up front.** `buildProfiles` makes the noisy weather from the seed, and `step()` uses no randomness. A day is a pure function of (scenario, seed, actions), so share links are fair and the Web Worker run matched the main-thread run exactly (B, $11.31M, checked in the browser).
- **The tutorial teaches by doing.** A coal unit trips at 00:00, time freezes, and one coach mark asks you to drag peakers. Time resumes at half speed, the needle recovers, and one more card explains the forecast lines. It takes about 15–20 s. After that, contextual hints (high frequency, sagging, sunset in 3 h, battery low, first shed, first trip, AI checkpoint) fire once per game.
- **Every other day opens paused** with a one-line briefing on what makes it hard. Space or "Start the day" begins.
- **No dependencies at all**, not even a font. The display face falls back from Bahnschrift/DIN to Arial Narrow, and numbers use the system monospace.

## v1.1: daily challenge, ghost, code par, share polish

- **Daily (`src/daily.js`, pure).** UTC date key -> day number (Daily #1 = Tue 17 Nov 2026, earlier dates preview as #1), FNV-1a seed, scenario from the fixed rotation `heatwave, windless, ai2030, spring, storm`, then twists from a seeded rng: new weather seed, peak demand ±3%, one surprise outage (09:00 to 20:30; before 12:00 and never coal on the heatwave; never stacked on the scenario's own outage of the same fleet). **The storm is special-cased**: it keeps its own seed and sizes and only moves each scripted outage by ±5 min, because it is a knife edge (about a third of random storm seeds had no blackout-free reference run, even with no extra outage). I checked all 365 dates from launch: every one has a blackout-free reference run. A test pins seeds, rotation and the launch-day scenario, so changing any of it is a conscious act (it reshuffles every future daily).
- **Daily par is computed in the browser** (`referencePars` in `src/reference.js`, about 0.3 s, warmed 0.6 s after the day starts and forced at the end), because variants have no hand-tuned par. A date with no clean reference run gets par 0, i.e. no par and any clean run grades A. Par is rounded up to $10k there, to $100k in the static scenarios (kept, so grades did not move).
- **The counted run is the BEST finished run per date per mode** (`hold60.daily.<date>.<manual|code>`; `countRun` in `src/daily.js`, unit-tested): lowest score wins, ties keep the old one, the record keeps a `runs` counter. Fix pass 2 changed this from "first run counts" because a learning run (or a code run of the untouched starter, which Red team 2 hit at $73.5M) locked the day. A code run whose source equals the starter template (`isStarterSource`: line endings and trailing blanks ignored) is never counted and writes no ghost; the results card says "Template". Share text status: `best today` (`best run` when the grid is not today's), `replay`, `template run`. Tutorial and autopilot runs never count. Daily runs never touch the per-scenario "best grade" badges. Shipped baselines loaded unchanged DO count (only the starter is excluded).
- **Ghost** (`src/ghost.js`): best finished run per scenario or date (lowest score, any mode, assisted runs excluded) is stored as 480 integers (mHz every 3 min, ~3 KB) under `hold60.ghost.<sc.id|daily.date>`; corrupt or missing data means no ghost. It is drawn in a new **frequency lane** under the chart (live trace in ink, ghost in grey, 59.3 Hz dotted). I chose frequency over generation because generation just hugs demand and tells you nothing. Code-mode re-runs pick up the latest ghost.
- **Code par** (`codePar` on each scenario, `gasFirst` in `src/reference.js`): best zero-blackout score across baselines, expert, reactive, tunedSimple and gas-first. Gas-first was found by a small grid search; it beats par on spring (-19.5%), heatwave (-1.0%) and AI (-8.7%), blacks out on storm and windless (so code par there is the expert, $14.07M and $10.16M). **Correction to the earlier note**: it does not beat par on day 4, and the "day 5" win only needs reserve and battery parameters the earlier simple version lacked. Manual grades are unchanged (par). The code table shows "vs par" and "vs code par"; the share text for code runs shows both.
- **Reference policies moved** from `tools/expert-policy.mjs` to `src/reference.js` (the app needs them for daily par); the tools file re-exports, so tests and scripts still import from there. They ship in the page's source now, which is already true of everything else; "hidden" means not in the editor.
- **Storm card** (`real` on the storm scenario, shown in any mode and on the daily storm): 4 sentences, hedged, no figures, names FERC and NERC; README cites the sources. A test limits it to 3 to 4 sentences and bans numeric claims.
- **Dated links and the friend banner** (`src/route.js`, pure, total): `#daily/YYYY-MM-DD[?g=B&s=11.3]` and `#code/daily/...`. Dates must be real calendar dates >= 2000; future dates clamp to today, malformed ones fall back to today, and the address bar is repaired (`canon`) with `history.replaceState`. `g` must be a grade and `s` a score in (0, 1000) $M, else the challenge is ignored. Case and a trailing slash are forgiven. The banner reads "A friend got B ($11.3M) on Daily #N — can you beat it?", shows a tutorial link to first-timers, is dismissible, and the results card says whether you beat the score. A viewer whose clock is behind the sharer's gets their own today (future dates clamp); dates before #1 still preview as #1.
- **First-run flow**: `tutorialDone` unset => the landing button is "Learn the grid, 30 s (then Daily #N)" -> `#tutorial?then=daily[/date]`; its last coach card says "Play today's grid" and navigates there (the full autopilot day is only offered on a plain `#tutorial` replay). Returning players get `#daily` directly. First blackout or trip of a non-tutorial manual run auto-pauses once (`autoPause`), 0.5× speed added (key 4).
- **Phone**: on <=980 px a sticky header (mini dial + readout + `minichart.js` day chart: forecast, net demand, demand, generation, now) shows when the big dial scrolls away; `overscroll-behavior-y: contain` on the game screen. **Resume**: manual daily runs save their control changes (`actLog`, one entry per control per game minute) every game hour and on `pagehide`/`visibilitychange`; on reload `Resume your run` replays the deterministic sim to that minute (`resumeRun`). The test hook marks a run `hooked`, which disables saving.
- **Code-mode table**: default columns Policy, Dark (MWh), Score, vs code par, Grade (vs par instead when a day has no code par); Fuel & ops, CO2 and vs par are behind a "Details" toggle (`.cmp`, delegated click). Fits 278 px with no scroll; opening details scrolls horizontally.
- **Sharing**: `navigator.share({text})` when it exists (the main button says "Share result", plus a "Copy text" button), clipboard otherwise. Cancelling the sheet is silent. Not tested on a real phone: only a stubbed `navigator.share` in Chromium.
- **og-card.png** (1200x630) is rendered by `tools/og-card.html` from the game's own dial, sim and palette. `index.html` has relative `og:image`, `twitter:image` and `twitter:card=summary_large_image`; **make them absolute after deploy** (README step 5). The old `screenshots/og-card.png` is deleted.

## v1.3: polish pass

- **Code-mode warnings** (`src/policy-check.js`, pure). `checkAction(action, kind)` returns `{id, key, text}` warnings for unknown keys (with a "did you mean" within 2 edits or by case, and a special line for `nuclear`), NaN/Infinity, non-numbers, a non-boolean `dr`, a non-object `commit`, unknown `commit.*` and `setpoints.*` keys, and a return value that is not an object. Returning nothing (`undefined`) is fine. The page shows each `id` once per run in the console as an amber `⚠ 06:30 ...` line (12 max, then "more warnings hidden"). The worker had to change for this: JSON turns NaN into `null`, so it replaces non-finite numbers with a `__nonfinite:` marker before the JSON round trip and sends `kind` (`typeof`, with `null`/`array`/`unserializable`). **One behaviour change**: `commit: { gas: NaN }` used to arrive as `null`, which the sim reads as "release the commitment"; it now arrives as a string and is ignored.
- **Syntax-error line numbers.** V8 gives no position for a SyntaxError from `new Function` (the old worker regex even matched an unrelated line, "line 1"), so the worker now sends no line for compile SyntaxErrors and `PolicyRunner.start` calls `locateSyntaxError` on the main thread (parsing never runs the code). It compiles every prefix of the code, closing open brackets, templates and comments first (`openThings` is a small lexer), and reports the first line from which every longer prefix fails; a statement that continues on the next line fails transiently and is skipped. If every closed prefix compiles, the code just ends early and it points at the last line ("the code ends before it is complete"). The engine's message can still be odd for wrapper reasons (`Unexpected token ')'`). Verified in Chromium only; the logic is engine-agnostic but the Firefox and Safari messages were not looked at.
- **Headroom cue** (`headroom()` in `src/ui/dial.js`, exported and tested). Above 60.3 Hz the status pill reads "Trip in 0.16 Hz" in the same warn styling as Sagging and Running high, turning red and pulsing (like Load shed) within 0.1 Hz of 60.5; the "trip" label on the dial takes the same colour and a dotted segment fills the gap between the needle and the trip line (also on the phone mini dial). Load shed still wins the pill text. The help dialog mentions it.
- **Daily par off the main thread** (`src/par-worker.js` is a *module* worker because it imports `reference.js`; `src/par-client.js` has `computePars(sc, {makeWorker, compute, timeoutMs})`). The worker starts as soon as a daily opens (it used to be a timer at 0.6 s). If `new Worker` throws, the worker errors, answers badly or is silent for 15 s, the same numbers are computed on the main thread (unit-tested with fake workers). `ensurePar` is still the synchronous path used when a day ends before the answer arrives (hook-finished runs, a very fast code run). Checked in Chromium: worker and main thread give identical par, `sc.parVia` says which one ran, and with `Worker` stubbed to throw the fallback gave the same numbers. Needs module-worker support (Chrome 80, Safari 15, Firefox 114); older browsers silently take the fallback.
- **Footer** on the landing page and the results card: Source, How it works, MIT. Source and How it works point at `https://github.com/<you>/hold-60` (and `#how-the-simulation-works`) and are dead until README deploy step 6 is done; MIT links to the `LICENSE` file next to the page. A test checks that both footers exist and that the README anchor heading exists.
- **Coach bubble vs the legend** (`placeCoachBox` in `src/ui/coach-place.js`, pure, tested with the real desktop and phone rectangles). Every coach bubble is placed below its target, else above, and must not touch the chart legend; if neither side is clear it tucks under (or over) the legend with its arrow hidden. The daily intro on the two-column layout is anchored under the dial panel (no highlight ring, because the ring turned the sticky panel into a relative one and made it jump); on phones it is still anchored under the topbar, which was already clear of the legend.
- **Screenshots re-taken in the light theme**: `code-mode-desktop.png` (Look-ahead running to 19:44, paused, console visible), `picker-desktop.png` (with the Daily card and sample best grades A+ and F), `game-desktop.png` (heatwave 18:58), all at 1360x860, and `game-mobile.png` at 390x844 (storm, 18:40, load shed). The browser clock was pinned to launch day (17 Nov 2026) so the Daily card reads "#1 · Tue 17 Nov, Texas-Style Heatwave".

## Known issues / rough edges

- **The windless margin is thin.** The expert beats look-ahead by 0.25%. Any change to sim constants can flip the test `scenarios 3-5: a good hand-written policy beats every baseline`. That's what the test is for. Re-tune with `node tools/tune.mjs tools/expert-policy.mjs`.
- **The sim is chaotic near the edges.** Small parameter changes can push a borderline policy into a trip→shed cascade (seen while tuning the AI day). That's realistic but makes balancing fiddly.
- **Battery charging looks like over-generation on the chart.** Charging is drawn as part of the stack above the demand line instead of as a separate band below zero.
- **Demand shows pre-shed demand**, so during a blackout "Gen − demand" is negative by the shed amount. It now always equals Generation − Demand as displayed (it no longer subtracts the battery's auto-response).
- **No touch-specific gestures.** Sliders are native range inputs, which work on phones but are small-ish. They're tested at 390 px in a desktop browser, not on a real device.
- **Background tabs pause the game.** That's because it uses `requestAnimationFrame`, and it's intended.
- **Test hook.** `window.__hold60.advance(minutes, baselineId)` and `.finish()` exist for browser checks, screenshots and the GIF recording, so they are deliberately still in. A curious reader will find them. README deploy step 7 says exactly what to delete before launch (the block at the bottom of `src/app.js`; nothing else refers to it).
- **`og:image` and `twitter:image` are relative.** Most crawlers need absolute URLs; see README step 5.
- **Daily par is computed in a worker now** (v1.3, see below); the ~0.3 s main-thread hitch only returns in the fallback path (no module workers, or the worker fails or takes more than 15 s) and when a day is finished before the worker answered.
- **No streaks, no history.** The landing page shows today's grade only. A streak counter and a "yesterday's grid" link are the obvious next shareability steps.
- **Clock trust.** The date comes from the player's clock (UTC-converted); changing it plays another day's grid, and each date keeps its own counted run. Fine for a no-server game.
- **The grid hum** (Web Audio, off by default) is only lightly tested. There's no visual cue that sound is on apart from the icon.

- **Resume is by replay, not a snapshot.** Only manual daily runs are saved, one slot (a new daily overwrites it), the last save is the last game hour or the last time the tab was hidden. The ghost, hints and the one-time auto-pause are restored; the test hook disables saving. Not tried on a real phone: pull-to-refresh suppression (`overscroll-behavior-y`) is untested outside desktop Chromium emulation.
- **The share link carries the sharer's score in plain text**, so anyone can edit `?g=&s=` to fake a friend. The banner is a nudge, not a leaderboard.

## What I'd do next

1. (Done in v1.1 and fix pass 2: daily challenge, ghost, dated links, friend banner.) Next on that thread: streaks, a "yesterday's grid" link on the landing page, and a leaderboard-free "best of N attempts" line in the share text.

Smaller: draw battery charging below zero, add a 0.5× speed for the tutorial-shy, show predicted ramp feasibility ("gas can't reach this before 19:00") on the sliders, and a proper GIF for the README.
